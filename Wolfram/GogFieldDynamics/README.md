# GogFieldDynamics

`GogFieldDynamics` is the repository-local Wolfram package used by both
computational notebooks. It provides exact graph-of-graphs models and
diffusion visualizations from the Python enumeration data.

The package bundles complete unlabelled cubic-multigraph models for
`N = 2, 4, 6, 8`. From their integer transition counts it provides:

- exact Rule-A multiplicity matrices, including holding slots;
- exact Rule-B matrices with probability `1/(3N)` for each distinct target
  and the remaining probability assigned to staying in place;
- the degree-normalized Rule-B jump chain for explicit comparison;
- rational diffusion from a selected quotient class;
- native random trajectories;
- an optional SetReplace encoding for sampled trajectories; and
- an atlas, a click-to-inspect class viewer, and the diffusion interface
  embedded in the notebooks.

## Load from a checkout

Run this from the repository root in a Wolfram kernel:

```wolfram
PacletDirectoryLoad[
  FileNameJoin[{Directory[], "Wolfram", "GogFieldDynamics"}]
]
Needs["GogFieldDynamics`"]
```

The package is loaded directly by the notebook build and does not need to be
installed globally.

## Public interface

```wolfram
GogAvailableSizes[]
GogSmallModel[4]
GogTransitionCounts[4, "A"]
GogTransitionMatrix[4, "B"]
GogTransitionMatrix[4, "BJump"]
GogDiffusionState[4, "A", 1, 6]
GogRandomTrajectory[4, "A", 1, 12, 7]
GogTrajectory[4, "A", 1, 12, 7, Method -> "SetReplace"]
GogClassAtlas[4]
GogClassExplorer[]
GogDiffusionSnapshot[8, "A", 1, 12, 273, "PathSteps" -> 48]
GogDiffusionExplorer[]
```

`GogDiffusionState` always uses exact rational matrix multiplication. A
trajectory is a separate random realization: it is never used to estimate the
displayed distribution.

`GogClassAtlas[4]` shows the five-state GoG together with a separate, larger
drawing of the cubic multigraph represented by each vertex.
`GogClassExplorer[]` adds clickable GoG vertices and supports the bundled
sizes `N=2,4,6,8`.

For Rule A, `GogSetReplaceRules` repeats the singleton-hypergraph rule
`{{i}} -> {{j}}` once for each resolution-slot multiplicity. Random event
ordering therefore retains duplicate targets and self-holding events. For Rule
B, it creates one rule for every distinct positive nonself target and adds
`3N - q(i)` self-rules. Every class therefore has the same total of `3N`
equally likely rules. The
old uniform-neighbour walk is available as `"BJump"`; it is Rule B conditioned
on moving. SetReplace is optional for the native lab but required by the
integration test.

## Data provenance

[`Resources/Data/small-models.json`](Resources/Data/small-models.json) is
generated by
[`scripts/build_small_gog_models.py`](../../scripts/build_small_gog_models.py),
which calls the same complete transition generator as
[`gog_generate.py`](../../gog_generate.py). The resource stores canonical class
codes, simple-support edges, and Rule-A integer counts only. It does not store
the concrete edge choices or settlement maps needed for carrier-field
transport.

Regenerate or byte-check it from the repository root:

```sh
python3 scripts/build_small_gog_models.py
python3 scripts/build_small_gog_models.py --check
```

## Verification

With Mathematica and SetReplace installed:

```sh
make notebook-paclet-check
```

The test report validates class and slot counts, both stochastic matrices,
exact diffusion, rewrite multiplicities, and an actual SetReplace trajectory.
The broader `make notebook-check` also opens and renders the interactive
companion and checks its visual outputs, embedded definitions, and section
structure.
